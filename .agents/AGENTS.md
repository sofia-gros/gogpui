# プロジェクト: gpui-component の Go 完全移植

## 目標

Rust製 UIコンポーネントライブラリ `github.com/longbridge/gpui-component`(GPUI上に構築、shadcn/ui意匠、60+コンポーネント)を、
`github.com/gogpu/gogpu` エコシステム(gogpu本体 + gogpu/gg)上に **Go で完全移植** する。

「完全移植」の定義:

- 公開関数名・型名・メソッドシグネチャが Rust 版と 1:1 対応すること(Goの命名規則の範囲内で)。
- 挙動(hover/click/focus/disabled/open-close 等の状態遷移)が Rust 版と一致すること。
- 見た目(shadcn/ui 由来のデザイン)が Rust 版と一致すること。

## 正典(Source of Truth) — 推測・記憶での実装を禁止する

1. Rustソース: https://github.com/longbridge/gpui-component (特に `crates/ui/src`)
2. ライブコンポーネントギャラリー(WASM、ブラウザで動作): https://longbridge.github.io/gpui-component/
   - 見た目や挙動(特にスクロール追従・ホバー・クリック)に確信が持てない場合は、
     必ずブラウザでこのギャラリーを開いて実際の挙動を確認してから実装すること。
3. `docs/porting-pattern.md` — 確立済みの移植パターン(GPUI概念 → gogpu/gg概念の対応表)
4. `PORTING_LEDGER.md` — コンポーネント単位の進捗・API対応表

上記に書かれていない/確認できないことを「たぶんこうだろう」で実装してはならない。
不明な場合は実装を止めて質問するか、Exploreフェーズをやり直すこと。

## 絶対厳守ルール

1. **1タスク = 1コンポーネント(または1つの明確に閉じた変更単位)。**
   複数コンポーネントを同時に触らない。無関係なファイルを変更しない。

2. **未検証の完了宣言を禁止する。**
   「動作するはずです」「完璧に動作します」のような、実行結果を伴わない完了宣言は禁止。
   タスク完了を報告する場合、Walkthrough内に以下を **生の実行結果として** 貼ること:
   - 対象パッケージの `go test ./...` の実際の標準出力(全文、抜粋・要約ではない)
   - ゴールデンイメージ差分テストの差分スコア
   - 変更前/変更後のスクリーンショット
     これらを提示できない場合は「未検証」と明記し、完了扱いにしないこと。

3. **Explore → Plan → Execute → Verify を必ず踏む。**
   Planは実装前に Implementation Plan Artifact として提示し、承認を得てから着手する。
   承認なしにコードを書き始めない。

4. **オーバーレイ(ドロップダウン/ポップオーバー/ツールチップ)の座標計算に関する注意。**
   gogpu/gg はDOM/CSSではなく毎フレーム描画のイミディエイトモードGPU描画である。
   「開いた瞬間の座標を1度だけ計算してキャッシュする」実装を禁止する。
   アンカーとなるウィジェットの現在のレイアウト位置を **毎フレーム再計算** してから描画すること。
   (これがスクロール追従バグの典型的な原因である)

5. **既存の動作を壊した場合、そのタスクは失敗である。**
   タスク完了を報告する前に、影響範囲全体のテストスイートがgreenであることを確認すること。

6. **進捗・決定事項は全てファイルに書き出す。エージェント自身の記憶に依存しない。**
   新しいタスクを開始する際は、必ず `PORTING_LEDGER.md` と `docs/porting-pattern.md` を読み込んでから作業すること。

## コンポーネント移植の完了条件(Definition of Done)

- [ ] 公開API(関数名・型名・メソッドシグネチャ)がRust版と1:1対応している(`PORTING_LEDGER.md` に記録済み)
- [ ] ゴールデンイメージ差分テストが合格している(差分スコアを明記)
- [ ] hover / focus / click / disabled / open-close など主要な状態について、合成入力イベントによるユニットテストがある
- [ ] `go test ./...` が対象範囲で全てgreen
- [ ] `PORTING_LEDGER.md` のステータス列を更新済み

## Git運用について

Antigravityはブランチ操作やマージの扱いが不安定なことが知られている。
コンポーネント1つ = 1コミットを人間側で明示的に管理し、問題が出た変更は即座に
`git revert` できる状態を常に保つこと。Antigravityにブランチ操作そのものを任せない。

無条件に実行しない。APIキーや認証情報をコードやログに出力しない。
