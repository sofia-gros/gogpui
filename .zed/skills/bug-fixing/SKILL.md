# バグ修正用フロー (Bug Fixing Flow)

ユーザーからバグの報告や修正の依頼を受けた場合、以下の標準フローに従って解決にあたってください。このフローは確実なバグ修正と再発防止（Regression Prevention）を目的としています。

## 手順

1. **状況把握 (Understand the Bug)**
   - ユーザーからの報告やエラーログを分析し、何が起きているか（What is happening）と期待される動作（What should happen）を整理します。
   - 情報が不足している場合は、推測で修正を始めず、ユーザーに質問するかログ出力を仕込んで調査（Explore）を行ってください。

2. **再現テストの作成 (Write a Failing Test)**
   - **非常に重要:** いきなり製品コードを修正しないでください。
   - まず、報告されたバグをプログラム的に再現するテスト（ユニットテスト、合成イベントテスト、またはゴールデン画像テスト）を作成します。
   - このテストを実行し、テストが**失敗（Fail）**することを確認します。これによりバグの存在を証明します。

3. **修正 (Implement the Fix)**
   - 製品コード（コンポーネント等）を修正します。
   - 修正は必要最小限に留め、関連しないスコープ外のリファクタリングを混入させないように注意してください。

4. **検証 (Verify)**
   - 手順2で作成したテストを再実行し、テストが**成功（Pass）**することを確認します。
   - プロジェクト全体のテスト (`go test ./...` など) を実行し、既存の機能が壊れていないか（Regressionがないか）を確認します。

5. **報告 (Report)**
   - 修正内容と、実行したテストの結果をユーザーに簡潔に報告します。

## 注意点
- 万が一、UIの見た目に関するバグなど「自動テストでの再現・検証が極めて困難」な場合は、手順2をスキップし、Showcase等のマニュアル検証手順（手動確認）を提示してユーザーに目視での検証を依頼してください。
